# ADR-0001: スクリーンショットは応答で返す。ディスクには何も書かない

- Status: Accepted
- Date: 2026-09-21

## Context

`get_screenshot` はスキャンの PNG を取得し、**必ずディレクトリへ書いていた**
——呼び出し側の `workspace_root`、省略時はサーバー自身の `workspace_dir` ——
そしてパスとバイト数を返していた。4 MiB 以下の場合は加えて MCP の image content
としても返していた。

これは組織が 2026-09-06 に廃止した形である（bigquery-mcp RFP Item 2・艦隊全体）。

> 閾値を超えたものをサーバーが自分で決めたファイルに書き、パスを返す方式は廃止する。
> サーバーは呼び出し側の文脈窓を知り得ないし、閾値・書き込み先・読み戻し経路を
> サーバーごとに持てば艦隊全体で同じ機構を作り直すことになる。大きな応答をディスクに
> 置くのはエージェントランタイムの仕事である。サーバーに残るのは明示的な上限と、
> 落とした分の件数だけである。

組織 ADR-021 も同じ線を引いている。**産物**がファイルであるサーバーは作業ディレクトリを
保つが、**データ**をファイルに変えるサーバーは保たない。要求に応じて取得する
スクリーンショットはデータである。pcap-analyzer-mcp は ADR-0009 でこの決定を適用し
（`result_file`・`sample`・`delivery` を削除、`extract_objects` は産物がファイルなので
`work_dir` は保持）、voice-scribe も ADR-0011 で同じ理由から配送モードの切り替えを削除した。

このサーバーは取り残されていた。別の方向から露見した。`workspace_root` は ADR-021 §1 が
廃止した綴りでもあり、2026-09-21 に他のすべてのツールの引数を未知フィールドに対して
閉じたとき、このハンドラだけは「`work_dir` への移行が控えている」という想定で緩いまま
残された。移行は答えではない——その引数は存在してはいけない。

既定の書き込み先がそれを一層はっきりさせていた。`workspace_dir` はサーバー自身の
ディレクトリを指すので、返されるパスは通常の場合、呼び出し側が読めないパスだった。

## Decision

1. **上限内のスクリーンショットは MCP の image content として返す。** モデルが必要と
   するのはそれである。ページを*見る*必要があるからだ。
2. **上限を超えたスクリーンショットは報告し、配送しない。** 応答は `bytes`、
   `inline: false`、止めた上限を名指しする `note`、そして `screenshot_url`
   （urlscan.io 自身の PNG アドレス）を持つ。切り詰めはしない。PNG の半分は小さな絵では
   なく、何でもない。取得するかどうかはランタイムか人の裁量である。
3. **ディスクには何も書かない。** `workspace_root`・`workspace_dir`・
   `URLSCAN_LOOKUP_WORKSPACE`・`internal/workspace` を削除した。
4. **上限は運用者のもの**とし、`screenshot_max_bytes`
   （`URLSCAN_LOOKUP_SCREENSHOT_MAX_BYTES`）で既定 4 MiB とする。base64 は 1/3 膨らみ、
   インライン画像は会話の各ラウンドで再送されるからである。範囲は内側から述べる
   （`[1, 64 MiB]`）。NaN が範囲検査を通り抜けられないようにするためである。
5. **`URLSCAN_LOOKUP_WORKSPACE` は名前を挙げて読み込みを失敗させる。** 黙って無視すれば、
   運用者が有効だと思っている書き込み先を消すことになる——pcap-analyzer の ADR-0009 §5 の
   規則をここにも適用する。
6. **`get_screenshot` の引数も他のツールと同様に閉じる**（ADR-021 §4）。
   `additionalProperties: false` と厳格デコーダである。`workspace_root` が無くなった今、
   応答すべき廃止綴りは残っていないので、ADR の 1 リリース猶予には覆う対象が無い。

## Consequences

- **破壊的変更。** 応答から `screenshot_file` が、引数から `workspace_root` が無くなり、
  `URLSCAN_LOOKUP_WORKSPACE` を持つ設定では起動しない。ファイルとしてディスクに欲しい
  呼び出し側は、インライン画像を保存するか `screenshot_url` を取得する。
- image content を扱えないクライアントの呼び出し側は `inline: false` を渡し、サイズと
  URL を受け取る。
- サーバーは書き込み可能なディレクトリを一切持たなくなった。これは ADR-021 の作業
  ディレクトリ契約への移行ではなく、契約の対象から外れたということである。
